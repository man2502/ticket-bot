# Веб-панель

Управление поиском и бронированием билетов: пассажиры, процессы, брони,
настройки сервисов, разметка капч.

Панель **не содержит логики поиска**. Она хранит настройки, запускает ботов
(`railway-api/railway_check.py`, `airlines_api/api_check.py`) отдельными
процессами и показывает их вывод. Боты остаются работоспособными и из CLI.

## Установка

```bash
.venv/bin/python -m pip install -r requirements-web.txt
.venv/bin/python -m web.cli create-admin
```

Windows:

```cmd
.venv\Scripts\python.exe -m pip install -r requirements-web.txt
.venv\Scripts\python.exe -m web.cli create-admin
```

Учётной записи по умолчанию нет: панель ведёт к странице оплаты, и забытый
`admin/admin` здесь стоит слишком дорого.

## Запуск

```bash
./run_web.sh          # macOS / Linux
run_web.cmd           # Windows
```

По умолчанию `http://127.0.0.1:8000`. Адрес меняется переменными
`TICKET_HOST` и `TICKET_PORT`.

## Данные

Всё рабочее лежит в `web/data/` (в git не попадает):

| Файл | Что |
|------|-----|
| `ticket.db` | SQLite: пользователи, пассажиры, процессы, логи, брони |
| `secret.key` | ключ шифрования паролей в базе |
| `session.key` | ключ подписи cookie |
| `captcha/` | картинки нерешённых капч |
| `runs/` | временные `check.env` и `passengers.json` запусков |

**Про ключи.** Пароли T5/Railway, SMTP и ключ SMS хранятся в базе
зашифрованными, ключ лежит отдельным файлом. Копия `ticket.db` без `secret.key`
паролей не выдаёт. Потеря `secret.key` — пароли придётся ввести заново
(остальные данные целы).

На сервере ключи удобнее задавать переменными `TICKET_SECRET_KEY` и
`TICKET_SESSION_KEY` вместо файлов.

## Устройство

```
web/
  app.py         сборка приложения: роутеры, статика, страницы ошибок
  auth.py        вход, require_user / require_admin
  cli.py         команды обслуживания
  config.py      пути, порт, каталоги
  crypto.py      Fernet для секретов
  db.py          подключение к SQLite
  models.py      схема базы
  security.py    scrypt-пароли, cookie сессии
  templating.py  общий контекст шаблонов и меню
  routes/        по разделу на файл
  services/      логика без HTTP: валидация, справочники, уведомления
  templates/ static/
```

Роуты и логика разделены намеренно: `services/` не знает ни про FastAPI, ни про
ORM, поэтому валидацию можно прогнать тестами без поднятия приложения.

## Пассажиры

Список общий для самолётов и поездов: один человек и летит, и едет, а вести его
данные в двух местах — верный способ получить два написания фамилии в паспорте.

Проверки при вводе (`web/services/passengers.py`):

* имя и фамилия — только латиница, приводятся к верхнему регистру, как в паспорте;
* дата рождения — любой из привычных форматов, приводится к `ДД.ММ.ГГГГ`;
* номер документа — без пробелов и дефисов, уникален по всей базе;
* телефон — `61234567`, `861234567`, `+993 61 23 45 67` дают один результат;
* срок действия документа — предупреждаем, если уже истёк.

**Тип пассажира** по умолчанию не задаётся вручную, а считается от даты рейса:
младенец до 5 лет, ребёнок до 18. Считать «на сегодня» нельзя — ребёнок,
которому 18 исполняется до вылета, летит по взрослому тарифу.

Состав группы проверяется при создании процесса: ребёнок не поедет без
взрослого, а младенцев не может быть больше, чем взрослых.

Удалять пассажиров может только админ, и только если они не участвуют
в незавершённых процессах.

## Справочники

Станции поездов и аэропорты хранятся локально, в одной таблице, разделённые
полем сервиса. Так форма создания процесса открывается сразу и работает, когда
сайт перевозчика лежит — а лежит он обычно ровно тогда, когда билеты и ищут.

| Сервис | Источник | Записей |
|--------|----------|---------|
| Самолёты | `turkmenistanairlines.tm/ru/get_internal_ports` | 7 |
| Поезда | `api.railway.gov.tm/v2/stations` | 142 |

Аэропортов нет в iOS-API, поэтому берём их с сайта. В браузерном боте этот же
адрес дёргается через `page.evaluate`, но обычного HTTPS-запроса достаточно —
авторизация не нужна, браузер тоже.

При первом запуске панель наполняет пустые справочники сама. Дальше — кнопка
«Обновить» в разделе, доступном только админу.

**Пропавшие станции не удаляются, а помечаются как неактивные.** На станцию
могут ссылаться уже созданные процессы, и удаление оставило бы в базе процесс
с маршрутом «ниоткуда никуда». Вернулась в источник — снова станет активной.

**Недоступный источник не очищает справочник.** Пустой список хуже устаревшего:
с ним нельзя даже создать процесс. Ошибка показывается, старые записи остаются.
Пустой ответ от источника тоже считается сбоем, а не «станций больше нет».

## Настройки

### Секреты

Пароли SMTP, ключ SMS и пароли перевозчиков лежат в базе зашифрованными
и **никогда не отдаются в HTML** — форма показывает только признак «задан».

Правила работы с полем секрета одинаковы везде:

| Что ввели | Что произойдёт |
|-----------|----------------|
| пусто | значение не меняется |
| новое значение | заменяется |
| `-` | стирается |

«Пусто = не менять» существенно: иначе правка соседней галочки молча обнуляла
бы пароль, и выяснилось бы это в момент брони.

### Проверка связи

У почты и SMS есть кнопка «Отправить тест». Неверный пароль должен обнаружиться
сейчас, а не тогда, когда бронь создана, а ссылка на оплату не дошла. Для Gmail
нужен **пароль приложения** — обычный пароль сервер отклоняет с кодом 535,
и панель прямо это подсказывает.

### SMS-шлюз

Панель шлёт `POST` с телом JSON. Имена полей и способ передачи ключа
настраиваются: у разных провайдеров они разные.

* поле номера, поле текста, имя параметра ключа — задаются;
* ключ уходит в тело, в заголовок или в query — на выбор;
* ключ необязателен;
* адрес обязан быть `https` — ключ не должен уходить открытым текстом;
* повторов при сбое нет: шлюз мог принять запрос, и повтор дал бы второе SMS.

### Параметры сервисов

Свободного поля «проверять каждые N секунд» нет намеренно: боты стреляют
в фиксированные секунды минуты с небольшим разбросом, и произвольный интервал —
прямой путь к бану. Настраивается то, что настраивать безопасно: какие окна
включены, секунда первого окна, лимит поисков в час, паузы backoff.

Числовые поля ограничены с обеих сторон. Например, паузу после `HTTP 429`
нельзя опустить ниже 30 секунд — это гарантия бана вместо билета.

У поездов раздела доступов нет: API открытый. У самолётов нужны телефон
и пароль личного кабинета плюс пароль приложения — по ним бот сам получает
Bearer-токены и обновляет их, когда те протухают.
